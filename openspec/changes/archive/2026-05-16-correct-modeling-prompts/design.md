## 上下文

当前 LLM 建模存在三个问题：

1. "风险偏好"是 select 类型变量，不参与权重计算，但 prompt 只说"LLM 参考"，没有量化规则，导致每次建模靠 LLM 直觉决定是否在基准分中体现
2. trade_offs.delta 没有范围约束，LLM 可能给出悬殊值（+25 vs -35），天然放大锚定偏见
3. 旧版 `DECISION_DEVIL_PROMPT` 与新版 `DECISION_DEVIL_MODEL_PROMPT` 对同一规则存在矛盾

核心目标：在 prompt 层面约束 LLM 输出更合理的模型，而非依赖审查来事后发现问题。p

## 目标 / 非目标

**目标：**

- 风险偏好量化：LLM 在建模时输出显式的 `risk_adjustment` 映射表，前端/仿真引擎根据用户风险偏好类型查表加分
- delta 范围约束：prompt 限制 delta 绝对值 ≤ 20，同维度跨选项 delta 差值 ≤ 30
- 审查 prompt 一致：所有审查 prompt 统一 select 变量规则
- 评分公式纳入权重：权重从"闸门"变为"乘数"

**非目标：**

- 不改变蒙特卡洛采样逻辑（分布类型、参数不变）
- 不修改前端 UI 组件结构
- 不引入新的 LLM 模型

## 决策

### 决策 1：风险偏好作为 Option 层级的 `risk_adjustment` 字段

在 treeData 的每个 Option 节点新增 `risk_adjustment` 对象，包含三种风险偏好类型对应的基准分偏移量：

```json
"risk_adjustment": {
  "保守": { "offset": -5 },
  "均衡": { "offset": 0 },
  "激进": { "offset": 5 }
}
```

**为什么选此方案：**

- 不改变现有变量+权重体系，风险偏好独立于滑块变量
- `offset` 直接作用于基准分，简单直接
- 前端调参时可根据用户选择的类型实时查表，无需 LLM 再次调用

### 决策 2：评分公式将权重作为乘数

**现有公式：** `offset = (paramValue/100 - 0.5) * delta * 2`
**新公式：** `offset = (paramValue/100 - 0.5) * delta * 2 * weight`

**理由：** 权重目前只作为"闸门"（有权重才参与计算），实际分数偏移完全由 delta 决定。将权重作为乘数后，高权重维度对分数的影响更大，低权重维度影响更小，符合权重的语义。

### 决策 3：Delta 约束在 prompt 中声明 + 后端 validateModel 校验

- prompt 中声明 delta 范围（±20）和跨选项差值（≤30）
- 后端 `validateModel()` 新增校验：检查 delta 是否超出合理范围
- 双重保障：prompt 约束 LLM，后端兜底拦截

**为什么不只在 prompt 中约束：** LLM 可能忽略 prompt 中的数字约束，后端校验是必要的兜底。

## 风险 / 权衡

- **[风险]** 新增 `risk_adjustment` 后，旧版本 LLM 返回的模型不包含此字段，前端需处理缺失情况
  **→ 缓解：** `sanitizeModel()` 中补全默认值（所有风险偏好类型 offset=0）

- **[风险]** 权重作为乘数后，原有模型的分数计算结果会变化，已有用户可能感知到差异
  **→ 缓解：** 这是行为修正，不是 bug，且仅影响调参后的重算，不影响首次加载

- **[风险]** delta 约束过紧（±20）可能导致极端合理的场景被限制
  **→ 缓解：** 约束设为 ±20 是经验值，可在后续根据实际效果调整
