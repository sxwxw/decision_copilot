## 新增需求

### 需求:自动敏感性分析

系统 SHALL 提供 `runSensitivity()` 方法，对每个变量分别做 -20% 和 +20% 扰动，记录每次扰动后的排名变化。

#### 场景:计算排名稳定性
- **当** `runSensitivity()` 完成所有变量扰动
- **那么** 返回 `{ stability: "stable" | "partially_stable" | "unstable", flips: number }`

#### 场景:计算第一名差距
- **当** `runSensitivity()` 完成
- **那么** 返回 `{ gap_pct: number }`，表示第1名和第2名效用值的相对差距

#### 场景:识别关键变量
- **当** `runSensitivity()` 完成
- **那么** 返回 `critical_variables` 数组，列出导致排名翻转的变量

### 需求:敏感性结果展示

系统 SHALL 在底部面板的"敏感性分析"tab 中展示分析结果。

#### 场景:展示稳定性指标
- **当** 敏感性分析完成
- **那么** 展示排名稳定性（文字 + 星级）、第1 vs 第2 差距百分比

#### 场景:展示关键变量
- **当** 敏感性分析完成且存在 critical_variables
- **那么** 列出每个关键变量及其引发的排名变化

### 需求:手动触发

系统 SHALL 提供手动触发敏感性分析的入口。

#### 场景:用户手动触发
- **当** 用户点击"运行敏感性分析"按钮
- **那么** 执行 `runSensitivity()` 并更新展示结果
