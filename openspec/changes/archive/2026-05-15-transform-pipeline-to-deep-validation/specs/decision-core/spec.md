# spec: decision-core

## 修改需求

### 输入区
系统 SHALL 提供多行文本输入框用于用户描述决策问题
系统 SHALL 提供「快速建模」按钮触发 LLM 建模流程（原「提交建模」按钮）
系统 SHALL 在建模加载期间显示 loading 状态

#### 场景:用户提交建模请求
- 当用户在输入框中输入决策问题并点击「快速建模」
- 那么系统调用 `/api/decision/model` 接口
- 那么按钮显示 loading 状态

### 参数面板（元数据驱动）
系统 SHALL 根据 LLM 返回的 variables 数组动态渲染参数控件
系统 SHALL 支持 slider（权重滑块）和 select（变量选择器）两种控件类型
系统 SHALL ~~提供「重新模拟」按钮，支持用户调参后触发后端深度推演~~ 改为提供「深度验证」按钮（详见 deep-validation 规范）
系统 SHALL 保留蒙特卡洛仿真、敏感性分析等功能入口（如存在）

#### 场景:用户调整参数
- 当用户拖动滑块改变参数值
- 那么系统在前端本地实时重算分数（秒级响应）

## 移除需求

### 深度模拟独立入口
**Reason**: 功能与多 Agent 流水线高度重叠，且多 Agent 已改造为基于当前模型的深度验证能力，深度模拟的 sim_spec 补充和蒙特卡洛仿真功能已并入深度验证流程
**Migration**: 用户使用"深度验证"按钮替代原有的"深度模拟"功能。如需基于当前参数重新推演，可点击"深度验证"（会保留已有 options/weights 进行增强）
