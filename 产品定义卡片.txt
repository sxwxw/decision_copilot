用户故事
1.角色：需要在不确定环境中做出关键抉择的职场管理者、创业者或项目负责人。
2.场景：面临多个互斥选项（如：是否砍掉核心业务线、选择哪种技术架构），且变量错综复杂。
3.问题：传统“拍脑袋”缺乏依据，Excel 决策矩阵建模门槛高且无法处理维度间的逻辑对冲，LLM 直接给建议又显得“黑盒”不可信。
4.使用：输入决策诉求 → AI 瞬间构建逻辑沙盘 → 用户拨动滑块注入主观偏好 → 实时看到方案分数的“此起彼伏”与风险预警 → 导出专业级决策报告。
核心功能 
1. AI 建模：输入一句话，自动提取决策选项、识别影响维度、构建因果决策树
2. 动态打分：基于权重和 trade-offs 的加权公式，用户调整参数后分数实时偏移（非 LLM 二次调用）
3. 路径溯源：点击树节点查看完整推演链路，含概率、核心推动力、风险评估
4. 深度模拟：LLM 二次推演，生成 delta_analysis 对比文案和详细归因
5. 报告导出：一键导出 PDF 深度分析报告
AI 价值点
传统决策矩阵（加权打分表）需要用户自己识别维度、分配权重、估算分值——这本身就需要决策能力。本产品用 LLM 一次性完成建模最难的前置工作：从自然语言中提取选项、识别关键变量、构建因果树、推演路径概率。用户只需在 AI 生成的模型上"微调偏好"即可获得量化结果。LLM 负责"从无到有"，前端公式负责"实时响应"，两者互补。
关键交互
1. 左侧输入决策问题并点击"提交"，AI 在数秒内生成分层决策树和量化模型
2. 左侧参数面板自动生成滑块和选择器，用户拖动滑块调整偏好（如"风险控制"调高至 80）
3. 右侧决策树和底部方案概览实时响应，显示分数偏移、排名变化和归因文案（如"你重视风险控制，该方案在此项不足"）
4. 点击"深度模拟"触发 LLM 二次推演，生成带对比分析的完整报告

环境准备
1. 确认 Node.js 版本 >= 18.0
2. 在项目根目录执行 npm install 安装依赖
3. 复制 .env.example 为 .env（如已有 .env 则跳过），确保 DASHSCOPE_API_KEY，DASHSCOPE_API_URL ，DECISION_MODEL，SIMULATE_MODEL，USE_REAL_LLM=false 已配置
4. 打开两个终端窗口：
   - 终端 1：执行 npm run server:dev 启动后端服务（端口 3000）
   - 终端 2：执行 npm run dev 启动前端（默认端口 5173）
5. 浏览器访问 http://localhost:5173
操作流程
1. 输入问题：在左侧输入框中输入一个具体决策问题，如"300分高考，选985大学、大专院校还是出国留学？"，点击"提交"按钮
2. 观察建模：等待数秒，右侧将生成一棵完整的决策树，包含三个选项（985大学/大专院校/出国留学）及其因果分支；底部出现方案概览，显示各方案的基准分和排名
3. 调整参数：拖动左侧"风险控制"滑块从 50 调高至 80，观察底部方案排名的实时变化——"大专院校"分数上升、"出国留学"分数下降，同时出现归因文案
4. 深度模拟：滑块参数偏离默认值后，"深度模拟"按钮变为高亮，点击触发 LLM 二次推演，底部出现蓝色对比分析提示框，说明逻辑变化原因
5. 路径溯源：点击决策树上某个叶子节点（如"985大学 → 落榜风险 → 后果严重"），底部切换为路径溯源视图，显示到达总概率、综合评分和核心推动力
6. 导出报告：在路径溯源页面点击"导出深度分析报告 (PDF)"，自动生成包含完整推演链路的 PDF 文档

1. 不支持多用户/鉴权：所有操作为匿名单用户模式，无注册、登录、权限控制
2. 无数据持久化：刷新页面后当前模型和参数全部丢失，无数据库或本地存储
3. 仅桌面端演示：未做移动端适配，窄屏下布局可能错乱
4. 仅支持中文：界面和 LLM 输出均为中文，无多语言切换
5. 无多轮对话：每次 LLM 调用为独立新会话，不保留上下文
6. LLM 依赖 API Key：未配置 DASHSCOPE_API_KEY 时自动降级为静态 mock 数据，用户输入将被忽略
7. PDF 导出为客户端渲染：基于 html2canvas 截图，非服务端生成，分辨率受屏幕尺寸影响
8. 不支持多方案对比存档：无法保存多次模拟结果进行横向对比
9. 单用户单会话：不支持多人同时使用或团队协作
10. 仅演示核心流程：未做异常降级处理，LLM 返回格式异常时可能前端报错
11. LLM 调用超时风险：Serverless 函数默认 60 秒超时，深度模拟可能超过此时限
12. LLM调用额度有限，LLM 异常时可能前端报错

1. Node.js >= 18.0：前端构建和后端服务均依赖 Node.js 环境
2. DASHSCOPE_API_KEY：需在 .env 中配置 API Key，否则降级为静态 mock 数据，用户输入将被忽略
3. 网络可访问：本地部署时需能访问 DashScope API 地址（默认 https://token.longshine.com/v1/chat/completions）；Vercel 部署地址为外网（*.vercel.app），国内网络访问需科学上网
4. 两个端口需空闲：后端 Express 占用 3000 端口，前端 Vite 占用 5173 端口，需确保未被其他服务占用
5. mock 数据兜底：未配置 API Key 或 LLM 调用失败时，系统自动返回 server/mock/decisionModel.json 中的预置数据，功能演示不受影响
