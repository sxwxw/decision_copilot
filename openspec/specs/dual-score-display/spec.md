# spec: dual-score-display

## 需求

### 双分显示

系统 SHALL 在所有分数展示区域采用"计算分为主分 + LLM 基准分为副分"的双分显示策略。

#### 场景:推荐结论卡片展示双分

- **当** 用户进入决策页面且已有建模结果
- **那么** 推荐结论卡片中每个方案的主分展示前端计算后的 adjusted score（大号字体）
- **并且** 每个方案的副分展示 LLM 原始 scores 值（小号灰色字体，标注为"基准"）
- **并且** 当计算分与基准分差值绝对值 > 5 时，显示差异指示标签

#### 场景:差异指示样式

- **当** 计算分 > 基准分 + 5
- **那么** 显示绿色向上箭头，提示"更匹配您的偏好"
- **当** 计算分 < 基准分 - 5
- **那么** 显示黄色向下箭头，提示"与您的偏好存在冲突"

#### 场景:方案概览卡片展示双分

- **当** 用户点击根节点进入方案概览视图
- **那么** 概览卡片中的分数使用前端计算后的 adjusted score 作为主分
- **并且** 卡片 SHALL 显示该方案与基准分的差值

### 差异化权重计算

系统 SHALL 使用差异化敏感度公式计算各方案的调整后分数，而非对所有方案施加相同的全局偏移量。

#### 场景:滑块调整触发分数重排

- **当** 用户调整任一参数滑块
- **那么** 系统 SHALL 重新计算所有方案的 adjusted score
- **并且** 计算公式为：`base + Σ((paramValue/100 - 0.5) × delta × 2)`，其中 delta 取自该方案 `logic_payload.trade_offs` 中对应维度的值
- **并且** 方案的排序 SHALL 可能因差异化偏移量而发生改变

#### 场景:中性滑块位置不改变分数

- **当** 所有参数滑块均处于默认值 50
- **那么** 所有方案的 adjusted score SHALL 等于 baseScore（无偏移）
