## 上下文

当前系统的所有定量计算（概率、权重、delta、分数）都由 LLM 直接输出。这导致三个问题：1) LLM 不擅长数学约束，产生路径概率和≠1.0 等数理错误；2) 每次建模都需要 LLM 生成精确数值，算力浪费；3) 用户无法理解分数来源，黑盒感强。

现有基础设施已具备：`src/engines/probNormalizer.js`（概率归一化）、`src/engines/pipelineStateMachine.js`（状态机）、`src/shared/modelValidator.js`（校验网关）。需要将它们组装为"数理映射层"，而非从零实现。

## 目标 / 非目标

**目标：**
- LLM 仅输出定性标签（极高/高/中/低/极低）和拓扑结构（选项、路径、事件关系）
- 确定性代码将定性标签映射为量化初始值（概率归一化、delta 查表、权重归一化）
- V2 外回路三锁：静态校验 → 置信度压制 → Nexus 显式批判
- 前端展示影响方向而非高频跳动的绝对分数

**非目标：**
- 不改变现有 API 接口契约（前端兼容性）
- 不改变 Monte Carlo 仿真引擎（simulator.js）
- 不将权重分配改为纯代码规则（保留 LLM 输出初始权重，代码仅做归一化）

## 决策

### 1. 定性标签粒度：五档制

采用"极高 / 高 / 中 / 低 / 极低"五档，而非三档。理由：三档无法表达肥尾效应和黑天鹅事件（如合规归零风险）。概率标签定义矩阵：

| 标签 | 基准值 | 容错范围 | 决策心理学语义 |
|---|---|---|---|
| 极高 | 0.90 | 0.85 - 0.95 | 几近必然 |
| 高 | 0.70 | 0.60 - 0.80 | 高度可能 |
| 中 | 0.50 | 0.40 - 0.60 | 可能性相当 |
| 低 | 0.25 | 0.15 - 0.35 | 不太可能 |
| 极低 | 0.05 | 0.01 - 0.10 | 黑天鹅/罕见 |

"极低"映射为 0.05 而非 0.15，确保蒙特卡洛仿真中肥尾路径不被过度抽样激活。

### 2. Prompt 改造：动态双轨解析器

**方案 A（已选）**：Prompt 要求 LLM 输出定性标签，但代码层不假设输入一定是标签。`sanitizeModel` 中实现"动态双轨解析器"：

- 如果 LLM 吐出纯数字（如 `probability: 0.7`），清洗器反向将其转换为对应标签（0.7 ∈ [0.60, 0.80] → "高"），再过统一归一化引擎
- 如果 LLM 吐出标签（如 `"probability_label": "高"`），正常查表映射

**选择 A 的理由**：彻底免疫 LLM 惯性幻觉。大模型在被投喂数千 Token 后仍可能直接输出数值，双轨设计保证管线不因字段类型冲突而击穿。

### 3. 定性→定量映射表放在 `src/shared/qualitativeMap.js`

新建独立文件，包含：
- 概率标签映射表（五档 → 基准值 + 容错范围）
- Delta 标签映射表（七档：强正向/中正向/弱正向/无影响/弱负向/中负向/强负向）
- 反向映射函数（数值 → 标签），供双轨解析器使用

### 4. 权重分配：维持 LLM 输出 + 代码归一化

不将权重分配改为纯代码规则。理由：权重跨行业语境差异极大（医疗AI中风险权重极高，内部工具中速度权重更高）。这种上下文判断是 LLM 强项。

折中方案：LLM 输出权重相对初始值（如 40:30:30），代码层 `sanitizeModel` 使用 `probNormalizer.js` 对权重数组进行刚性归一化，确保总和绝对等于 1.0。

### 5. V2 外回路三锁：可解释性设计

- **第一锁**：V2 build-model 完成后立即调用 `validateModel()`，收集 error
- **第二锁**：发现 error 时在 confidenceSignals 中注入结构化标签 `override_reason: "底层因果图发生断头路，量化底座失效"`，Nexus 完成后若仍有 error 则强制将 `confidence_level` 设为 40
- **第三锁**：将校验错误信息注入 Nexus Prompt，使终审 Agent 在报告中批判量化基础。前端 NexusReport 渲染时读取 `override_reason` 标签，显示橙色标牌："系统已介入安全干预，将综合置信度强制锁定在 40。"

消除"为什么 AI 得出这个分数"的二次黑盒感。

### 6. 内回路触发：保留 DEVIL 判断 + 扩展定量触发

定量校验的 error 级别直接触发内回路。warning 级别（概率和异常）注入到 DEVIL 审查上下文中，由 LLM 判断是否升级为 CRITICAL。最多执行 1 次。

## 风险 / 权衡

| 风险 | 缓解措施 |
|---|---|
| LLM 仍可能输出数值（惯性行为） | 双轨解析器兜底：数值反向转标签 → 统一映射，不报错 |
| 五档标签容错范围过窄导致映射失败 | 容错区间设计为宽松范围（如"高"对应 0.60-0.80），超出范围的值 fallback 到最近档 |
| V2 强制锁死置信度 40 可能过于激进 | 仅在 error 级别时触发，warning 不触发。且通过 override_reason 标签提供可解释性 |
| 修改 Prompt 可能破坏现有 mock 数据兼容性 | mock 数据仅在开发阶段使用。真实环境 USE_REAL_LLM=true。双轨解析器可兼容旧格式 |

## 迁移计划

1. 先完成 `qualitativeMap.js` 映射层 + 双轨解析器
2. 改造所有 Prompt 文件，加入五档标签约束

4. 增强 `executePipelineSteps` 的三锁机制（含 override_reason 标签）
5. 更新 mock 数据（如仍使用）
